# Render Template And Commit

Renders a Handlebars template to a file and commits the result as a verified bot commit, skipping the commit when the render changed nothing.

[actions-common-render-template-and-commit-v1.1.21](https://github.com/TimSchoenle/actions/releases/tag/actions-common-render-template-and-commit-v1.1.21) · Composite action
<!-- /docs:generated header -->

Regenerating a checked-in file always needs the same two steps, render and commit. This action is that pairing in
one step. It composes two released actions and adds nothing of its own beyond the wiring:

- [`common/render-template`](../render-template) writes the file from a [Handlebars](https://handlebarsjs.com/)
  template.
- [`common/commit-changes`](../commit-changes) commits it through the GraphQL API, so GitHub signs the commit.

The commit step is **skipped when the render changed nothing**. Rendering is deterministic, so a scheduled regeneration
over unchanged inputs makes no commit and no API call.

## Usage

### Render and commit

```yaml
- name: Check out the repository
  uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1

# The commit needs a GitHub App installation token with contents: write.
- name: Create an app token
  uses: actions/create-github-app-token@64ab729a6294000f5aa4a4bc0b73d1f32bc45510 # v3.3.0
  id: token
  with:
    client-id: ${{ secrets.BOT_APP_CLIENT_ID }}
    private-key: ${{ secrets.BOT_PRIVATE_KEY }}
    permission-contents: write

- uses: TimSchoenle/actions/actions/common/render-template-and-commit@0701d3b35ad7e10e3159471c82f4743b67fdc01f # tag=actions-common-render-template-and-commit-v1.1.21
  id: docs
  with:
    template: docs/README.hbs
    output: README.md
    partials-dir: docs/partials
    variables: ${{ steps.collect.outputs.data }}
    token: ${{ steps.token.outputs.token }}
    commit_message: 'docs: regenerate README'

- run: echo "Committed $COMMIT_URL"
  if: steps.docs.outputs.changes_detected == 'true'
  env:
    COMMIT_URL: ${{ steps.docs.outputs.commit_url }}
```
<!-- /docs:generated usage -->

The template, its partials and the output path are all read from and written to the workspace, so **the caller owns the
checkout**. This action does not check anything out, which is what lets it run mid-workflow, after whatever step produced
the variables.

See [`common/render-template`](../render-template) for the template language, the helper set, strict mode and partial
resolution. Every rendering input behaves exactly as it does there.

### `file_pattern`

By default only the rendered file is committed, not the whole workspace. That is the difference that matters when a
build step left artefacts behind: a documentation commit stays a documentation commit.

Override it to commit more, using the same pathspec syntax `commit-changes` accepts:

```yaml
file_pattern: 'README.md SECURITY.md docs/**/*.md'
```

The override is used verbatim; it is not merged with the output path, so an override that does not match the rendered
file will not commit it.

### `check` is deliberately not exposed

`render-template`'s `check` mode writes nothing, which leaves this action nothing to commit. Use `render-template`
directly with `check: true` for a CI gate that verifies a committed file is current.

## Outputs

| Output             | Description                                                                                                                                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `changed`          | true when the rendered content differed from what was already at the output path. It describes the file on disk, not the branch.                                                                                                                                                           |
| `checksum`         | SHA-256 of the rendered content, as lowercase hex.                                                                                                                                                                                                                                         |
| `output-path`      | Path the rendered content was written to, as given.                                                                                                                                                                                                                                        |
| `commit_hash`      | The SHA of the created commit. Empty when the render changed nothing and no commit was made.                                                                                                                                                                                               |
| `commit_url`       | The URL of the created commit. Empty when the render changed nothing and no commit was made.                                                                                                                                                                                               |
| `changes_detected` | true when a commit was made, false otherwise. Never empty, even when the commit was skipped. It describes the branch, not the file on disk: a render that changed the workspace file but matched what was already committed on the branch reports changed true and changes_detected false. |
