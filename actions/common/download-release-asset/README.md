# Common Download Release Asset

Downloads a GitHub release asset, through the REST API asset endpoint when the release download fails, and verifies it against a pinned SHA-256 or a pinned checksums file.

[actions-common-download-release-asset-v1.1.3](https://github.com/TimSchoenle/actions/releases/tag/actions-common-download-release-asset-v1.1.3) · JavaScript action (node24)
<!-- /docs:generated header -->

The release download URL (`github.com/<owner>/<repo>/releases/download/<tag>/<asset>`) is tried first, three
times. When it still fails with a 5xx, a timeout or a connection error, the action looks the release up through
the REST API, picks the one asset with that exact name, and downloads it from the asset endpoint by its numeric
ID. A 404 is not retried that way: the asset does not exist. Both routes feed the same verification.

## Usage

### Pin the asset itself

```yaml
# The version and the SHA-256 are pinned side by side, so an update changes both in one place. The
# asset name is derived from the version rather than written out, so it never falls behind the tag.
- id: release
  env:
    JACTIONLINT_VERSION: 'v2.5.0'
    JACTIONLINT_SHA256: '5cbf573f7d3828a6e679c35520f1bd00c512ec7bde31a281e40808ba68c8225c'
  run: |
    {
      echo "tag=${JACTIONLINT_VERSION}"
      echo "asset=jactionlint_${JACTIONLINT_VERSION#v}_checksums.txt"
      echo "sha256=${JACTIONLINT_SHA256}"
    } >> "$GITHUB_OUTPUT"

- id: download
  uses: TimSchoenle/actions/actions/common/download-release-asset@actions-common-download-release-asset-v1.1.3 # tag=actions-common-download-release-asset-v1.1.3
  with:
    repository: jdx/jactionlint
    tag: ${{ steps.release.outputs.tag }}
    asset: ${{ steps.release.outputs.asset }}
    sha256: ${{ steps.release.outputs.sha256 }}
```

### Pin the release's checksums file

```yaml
# One digest covers the asset on every platform. The checksums file is downloaded and checked
# against checksums-sha256 first, so a wrong pin fails before the asset is downloaded. It must be in
# sha256sum format and list the asset exactly once. The version and the checksums file's SHA-256 are
# pinned side by side, so an update changes both in one place.
- id: release
  env:
    JACTIONLINT_VERSION: 'v2.5.0'
    JACTIONLINT_SHA256: '5cbf573f7d3828a6e679c35520f1bd00c512ec7bde31a281e40808ba68c8225c'
  run: |
    version="${JACTIONLINT_VERSION#v}"
    {
      echo "tag=${JACTIONLINT_VERSION}"
      echo "archive=jactionlint_${version}_linux_amd64.tar.gz"
      echo "checksums=jactionlint_${version}_checksums.txt"
      echo "checksums-sha256=${JACTIONLINT_SHA256}"
    } >> "$GITHUB_OUTPUT"

- id: download
  uses: TimSchoenle/actions/actions/common/download-release-asset@actions-common-download-release-asset-v1.1.3 # tag=actions-common-download-release-asset-v1.1.3
  with:
    repository: jdx/jactionlint
    tag: ${{ steps.release.outputs.tag }}
    asset: ${{ steps.release.outputs.archive }}
    checksums-asset: ${{ steps.release.outputs.checksums }}
    checksums-sha256: ${{ steps.release.outputs.checksums-sha256 }}

- run: tar -xzf "$ARCHIVE" -C "$RUNNER_TEMP" jactionlint
  env:
    ARCHIVE: ${{ steps.download.outputs.path }}
```

## Token

The token goes only to `api.github.com`, only for the fallback, and only when `GITHUB_SERVER_URL` is
`https://github.com`: a GitHub Enterprise Server token is not a github.com credential. The release download itself
is anonymous. The asset URL is built from the numeric ID rather than read from the API response, and the
`Authorization` header is dropped when the asset endpoint redirects to the storage host.

The token keeps the fallback clear of the anonymous rate limit of 60 requests an hour per IP address. Any token
works. Only public releases are supported: the anonymous release download answers 404 for a private asset, and a
404 ends the download instead of starting the fallback.

## Proxies

Requests honour `HTTPS_PROXY` and `NO_PROXY` (or their lower-case forms) on self-hosted runners, by the same rules
`@actions/http-client` applied, credentials in the proxy URL included.
