# Common Find Patch

Reports whether a run uploaded a non-empty common/create-patch artifact, without any secret, so a workflow_run job can skip minting a write token when there is nothing to commit.

[actions-common-find-patch-v1.1.2](https://github.com/TimSchoenle/actions/releases/tag/actions-common-find-patch-v1.1.2) · Composite action
<!-- /docs:generated header -->

The artifact is the one [`common/create-patch`](../create-patch) uploads. A `workflow_run` workflow runs this action
in a job of its own ahead of the job that mints the write token for [`common/commit-patch`](../commit-patch), and
skips that job when there is nothing to commit: the producing job was skipped, its patch is empty, or the patch was
made from another commit than `expected_head_sha`.

It compares the patch with `expected_head_sha` only, which in a `workflow_run` workflow is the commit the producing run
checked out, not the branch as it is now. A branch that moved on after a non-empty patch was made still reports
`changes` and starts the token job; `commit-patch` then checks the branch itself and ends with `branch_moved`.

The artifact is validated exactly as `commit-patch` validates it. A malformed one fails the step instead of reading as
"nothing to commit", so a broken producer shows up as a red run, not as a pull request that silently never gets its
commit.

GitHub can list an artifact a few seconds after the upload that created it finished. When `run_id` is empty or names
this run, an artifact a job of this run just uploaded may not be listed yet, so the action lists again after 1, 2, 3
and 4 seconds before it settles on `missing`: at most five listings and 10 seconds, and only when the artifact is not
there. Expect that wait when the producing job of this run was skipped. Another run's listing, such as the
`workflow_run` producer's, is read once and never waited on.

## Usage

### Skip the token job when there is nothing to commit

```yaml
name: Auto Format Commit

on:
  workflow_run:
    workflows: ['Auto Format'] # the name: of the pull_request workflow
    types: [completed]

permissions: {}

jobs:
  # Holds no secret and no environment.
  find-patch:
    # Accepting a failure conclusion lets a producer fail its own check while its patch is still
    # uncommitted, so the head it ran on cannot merge before the bot commit lands, and still have
    # that patch committed.
    if: >-
      (github.event.workflow_run.conclusion == 'success' || github.event.workflow_run.conclusion == 'failure') &&
      github.event.workflow_run.event == 'pull_request' &&
      github.event.workflow_run.head_repository.full_name == github.repository &&
      github.event.workflow_run.head_branch != github.event.repository.default_branch
    runs-on: ubuntu-latest
    permissions:
      actions: read # to list and download the pull_request run's artifacts
    outputs:
      has_changes: ${{ steps.patch.outputs.has_changes }}
    steps:
      - id: patch
        uses: TimSchoenle/actions/actions/common/find-patch@6a49261c7bbd756b4ceca9b1c168dfc7dc095e64 # tag=actions-common-find-patch-v1.1.2
        with:
          run_id: ${{ github.event.workflow_run.id }}
          artifact_name: format-patch
          expected_head_sha: ${{ github.event.workflow_run.head_sha }}

  commit:
    needs: find-patch
    if: needs.find-patch.outputs.has_changes == 'true'
    runs-on: ubuntu-latest
    environment: ci
    permissions:
      actions: read
      contents: read
    steps:
      # checkout, create-github-app-token and commit-patch, as in the commit-patch README
```

## Behaviour

- **A missing or expired artifact is `missing`, not an error.** `create-patch` uploads even an empty patch, so no
  artifact means the job that makes it did not run. An artifact past its retention can no longer be downloaded, and a
  run that old has nothing left to commit.
- **A run that does not exist fails the step.** A mistyped `run_id`, or a token without `actions: read`, would
  otherwise skip every commit without a word.
- **Several unexpired artifacts of the same name, from re-run attempts, resolve to the newest.** download-artifact
  fetches the one with the highest ID, so that is the one inspected; the step logs a warning naming them all.
- **The outcome is the one `commit-patch` would end with against `expected_head_sha`.** A patch made from another commit
  than `expected_head_sha` is `branch_moved`, empty or not, reported with a notice; otherwise an empty patch is
  `no_changes`. The branch's current tip is not looked at: that is `commit-patch`'s check, made when it commits.
- **An archive larger than any create-patch artifact can be is refused before download.** That is `max_patch_bytes`
  plus 1 MiB for the metadata and archive headers, read from the artifact listing. It bounds the download, not the
  extraction: download-artifact extracts the archive before the reader checks what it holds.
- **Only the two files are read.** The artifact must hold exactly `changes.patch` and `metadata.json`, both regular
  files opened without following links, with the patch within `max_patch_bytes` and matching the size and SHA-256
  recorded beside it. Nothing in it is executed.
- The composite runs its TypeScript with the `node` on the runner's `PATH`; a self-hosted runner needs Node.js 20 or
  later installed.
