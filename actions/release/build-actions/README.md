# Release Build Actions

Builds JavaScript actions from source with a caller-supplied command, checks that every bundle their manifests name exists, and uploads the bundles with a manifest of their SHA-256 digests as one artifact for release/install-built-actions.

[actions-release-build-actions-v1.1.0](https://github.com/TimSchoenle/actions/releases/tag/actions-release-build-actions-v1.1.0) · Composite action
<!-- /docs:generated header -->

The first half of a build-then-test pipeline: one job builds the bundles from the commit under test and uploads them
as an artifact, and every job that runs those actions installs them with
[`release/install-built-actions`](../install-built-actions) first. Tests then run on bundles built from the commit
they test, never on a committed or cached copy.

The action installs no toolchain and no dependencies. Set those up before it, so the same action builds with Bun, npm,
pnpm or anything else a shell command can run.

## Usage

### Build and test in separate jobs

```yaml
name: Verify My Action

on:
  pull_request:

permissions: {}

jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read # to fetch code
    outputs:
      artifact-id: ${{ steps.build.outputs.artifact-id }}
      manifest-sha256: ${{ steps.build.outputs.manifest-sha256 }}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: oven-sh/setup-bun@0c5077e51419868618aeaa5fe8019c62421857d6 # v2.2.0
        with:
          bun-version-file: '.bun-version'
      - run: bun install --frozen-lockfile
      - id: build
        uses: TimSchoenle/actions/actions/release/build-actions@actions-release-build-actions-v1.1.0 # tag=actions-release-build-actions-v1.1.0
        with:
          build-dirs: |
            actions/my/action
            actions/my/other/helper
          build-command: bun run build
          artifact-name: built-actions-${{ github.run_attempt }}

  test:
    needs: build
    runs-on: ubuntu-latest
    permissions:
      contents: read # to fetch code
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: TimSchoenle/actions/actions/release/install-built-actions@actions-release-install-built-actions-v1.1.0 # tag=actions-release-install-built-actions-v1.1.0
        with:
          artifact-id: ${{ needs.build.outputs.artifact-id }}
          expected-manifest-sha256: ${{ needs.build.outputs.manifest-sha256 }}
      - uses: ./actions/my/action
```

### Build a single action at the repository root

```yaml
name: Build

on:
  pull_request:

permissions: {}

jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read # to fetch code
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version-file: '.nvmrc'
      - run: npm ci
      # action.yml at the root runs dist/index.js; the build writes it.
      - uses: TimSchoenle/actions/actions/release/build-actions@actions-release-build-actions-v1.1.0 # tag=actions-release-build-actions-v1.1.0
        with:
          build-dirs: .
          build-command: npm run build
          artifact-name: built-action-${{ github.run_attempt }}
```

## Behaviour

- **Inputs are checked before the build runs.** `build-dirs` must list directories of JavaScript actions: a composite
  or Docker action ships no bundle and fails the step. Take the list from
  [`release/resolve-actions`](../resolve-actions), which already expands composites to the helpers they run.
- **The build runs with bash** as the runner's default shell does (`--noprofile --norc -eo pipefail`), with the job's
  environment minus this step's `INPUT_*` variables. With `per-directory: true` it runs in each build directory with
  `BUILD_DIR` set; with `false`, once in `path` with `BUILD_DIRS` set to the newline-separated list.
- **Every entry point must exist afterwards.** The bundles are read from each manifest's `runs.pre`, `runs.main` and
  `runs.post` before the build runs, so a build that rewrites a manifest cannot change what is checked. A missing
  bundle, a symbolic link or anything but a regular file fails the step.
- **Only the bundles are uploaded**, at their repository paths, with `bundles.json` (schema 1: source commit,
  toolchain, build directories, and the path, SHA-256 and size of every file) and `bundles.sha256` in `sha256sum`
  format. Source maps and other files the build leaves next to a bundle stay out.
- **The manifest hash is the value to trust.** Publish `manifest-sha256` and `artifact-id` as job outputs and hand
  them to `install-built-actions`; it verifies every file against that hash. The artifact is uploaded with
  `overwrite: false`, so a second upload under the same name fails instead of replacing it.
- **No cache.** Building is cheaper than proving a cached bundle is the one this commit produces.
- The composite runs its TypeScript with the `node` on the runner's `PATH`; a self-hosted runner needs Node.js 20 or
  later installed.
