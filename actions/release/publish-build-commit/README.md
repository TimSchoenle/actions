# Release Publish Build Commit

Publishes bundles built by release/build-actions: a build commit B with the source commit tree plus the bundles, a fast-forwarded releases branch, consumer tags on B, source tags on the source commit, and GitHub Releases with checksum assets. Every step is idempotent and no repository code runs.

[actions-release-publish-build-commit-v1.0.0](https://github.com/TimSchoenle/actions/releases/tag/actions-release-publish-build-commit-v1.0.0) · Composite action
<!-- /docs:generated header -->

The privileged end of a build-on-release pipeline. The default branch holds sources only; this action turns a source
commit `M` and the bundles [`release/build-actions`](../build-actions) built from it into:

| Ref | Points at |
| --- | --- |
| build commit `B` | tree of `M` plus the bundles, nothing removed or changed; parents: the releases branch head, then `M` |
| `releases-branch` | `B`, moved by fast-forward only |
| each `consumerTag` | `B`: what consumers pin |
| each `sourceTag` | `M`: what release-please finds the previous release by |

and a published GitHub Release per consumer tag, with its notes and assets. `B` is created through the Git Data API
without author or committer, so GitHub signs it when the token is an App installation token.

## Usage

### Publish a release-please release from two agreeing builds

```yaml
name: Release

on:
  push:
    branches: [main]

permissions: {}

jobs:
  # plan: release/plan-release-please in plan mode, outputs is-release
  # build and build-verify: release/build-actions on two runners, outputs artifact-id,
  #   artifact-digest and manifest-sha256

  publish:
    needs: [plan, build, build-verify]
    if: needs.plan.outputs.is-release == 'true'
    runs-on: ubuntu-latest
    environment: release
    concurrency:
      group: release-publish
      cancel-in-progress: false
    permissions:
      actions: read # to check and download the build artifact
      contents: read
    steps:
      - id: token
        uses: actions/create-github-app-token@64ab729a6294000f5aa4a4bc0b73d1f32bc45510 # v3.3.0
        with:
          client-id: ${{ secrets.RELEASE_APP_ID }}
          private-key: ${{ secrets.RELEASE_APP_PRIVATE_KEY }}
          permission-contents: write
          permission-issues: write
          permission-pull-requests: write

      # Re-derived here, so the notes files exist in this job.
      - id: plan
        uses: TimSchoenle/actions/actions/release/plan-release-please@actions-release-plan-release-please-v1.0.0 # tag=actions-release-plan-release-please-v1.0.0
        with:
          mode: plan

      - uses: TimSchoenle/actions/actions/release/publish-build-commit@actions-release-publish-build-commit-v1.0.0 # tag=actions-release-publish-build-commit-v1.0.0
        with:
          token: ${{ steps.token.outputs.token }}
          source-sha: ${{ github.sha }}
          artifact-id: ${{ needs.build.outputs.artifact-id }}
          expected-artifact-digest: ${{ needs.build.outputs.artifact-digest }}
          expected-manifest-sha256: ${{ needs.build.outputs.manifest-sha256 }}
          cross-check-manifest-sha256: ${{ needs.build-verify.outputs.manifest-sha256 }}
          releases: ${{ steps.plan.outputs.releases }}
          pull-request: ${{ steps.plan.outputs.pull-request }}
```

### Publish a single action at the repository root

```yaml
name: Release

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version to release, such as 1.2.3.'
        required: true

permissions: {}

jobs:
  # build: release/build-actions with build-dirs: . for the action.yml at the root, outputs
  #   artifact-id, artifact-digest and manifest-sha256

  publish:
    needs: build
    runs-on: ubuntu-latest
    environment: release
    permissions:
      actions: read # to check and download the build artifact
      contents: read
    steps:
      - id: token
        uses: actions/create-github-app-token@64ab729a6294000f5aa4a4bc0b73d1f32bc45510 # v3.3.0
        with:
          client-id: ${{ secrets.RELEASE_APP_ID }}
          private-key: ${{ secrets.RELEASE_APP_PRIVATE_KEY }}
          permission-contents: write

      # Hand-written releases: one consumer tag, no source tag, notes from the workflow input.
      - id: releases
        env:
          VERSION: ${{ inputs.version }}
        run: |
          set -euo pipefail
          [[ "$VERSION" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]] || { echo "::error::version must be X.Y.Z"; exit 1; }
          notes="${RUNNER_TEMP}/notes.md"
          printf 'Release %s\n' "$VERSION" > "$notes"
          releases="$(jq -cn --arg tag "v${VERSION}" --arg notes "$notes" '[{consumerTag: $tag, releaseName: $tag, notesFile: $notes}]')"
          echo "releases=${releases}" >> "$GITHUB_OUTPUT"

      - uses: TimSchoenle/actions/actions/release/publish-build-commit@actions-release-publish-build-commit-v1.0.0 # tag=actions-release-publish-build-commit-v1.0.0
        with:
          token: ${{ steps.token.outputs.token }}
          source-sha: ${{ github.sha }}
          artifact-id: ${{ needs.build.outputs.artifact-id }}
          expected-artifact-digest: ${{ needs.build.outputs.artifact-digest }}
          expected-manifest-sha256: ${{ needs.build.outputs.manifest-sha256 }}
          allowed-paths: dist/**
          releases: ${{ steps.releases.outputs.releases }}
          release-assets: bundles
```

## Behaviour

- **Nothing is written before the bundles are verified.** The artifact record must belong to this run, be unexpired
  and carry `expected-artifact-digest`; download-artifact refuses an archive that differs from it; every file must match
  the manifest with `expected-manifest-sha256`, which must equal `cross-check-manifest-sha256` when a second build
  supplies one; the manifest's source commit must be `source-sha`; every bundle path must match `allowed-paths`.
- **`B` only adds files.** Its tree is computed locally from the directories on each bundle's path and git's own tree
  encoding, then checked against the tree GitHub creates; each blob id is checked the same way. With
  `existing-files: fail` a bundle path that exists in `M` fails the run; with `require-identical` it may exist with
  identical bytes, which leaves the tree equal to `M`'s.
- **Every step is an ensure, in a fixed order**: build commit and releases branch, tags, releases, pull request. A
  re-run after any failure finishes the job and reports what it changed in `created`; a re-run after success writes
  nothing and reports `[]`.
  - An existing consumer tag on a build commit of this source and tree is reused as `B`, as is a releases branch head
    that is one. A tag anywhere else fails the run: no tag is ever moved.
  - The releases branch is created or fast-forwarded. When it moves between the read and the update, the next build
    commit is chained on the new head, up to three attempts. A branch that has diverged from an existing `B` fails the
    run.
  - A published release is left alone. A draft on the tag, left by an interrupted run, has its assets replaced and is
    published. Two drafts on one tag fail the run.
  - The pull request gets one comment per source commit, then `tagged-label`, and loses `pending-label` last.
    release-please opens no new release pull request while a merged one is still pending, so a publish that failed
    part-way cannot be overtaken by the next release.
- **Assets.** `checksums` attaches `bundles.sha256`, the `sha256sum` lines of the bundles below the release's `path`
  (all bundles without one); a release whose path holds no bundle gets no asset. `bundles` attaches each of those
  bundles too, named by its path below the release path with `/` replaced by `-`.
- **`dry-run: true`** performs every check and read, computes `tree-sha`, and writes nothing. `build-sha` is empty
  unless an existing build commit was found.
- The action runs no repository code and builds no command from its inputs. Pin it by commit SHA. The composite runs
  its TypeScript with the `node` on the runner's `PATH`; a self-hosted runner needs Node.js 20 or later installed.
