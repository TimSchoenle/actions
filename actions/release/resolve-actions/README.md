# Release Resolve Actions

Resolves which actions of a checkout have to be built for a set of actions or workflows to run, or which a set of changed files affects: the build directories, the bundle paths and the source paths to filter triggers on.

[actions-release-resolve-actions-v1.1.2](https://github.com/TimSchoenle/actions/releases/tag/actions-release-resolve-actions-v1.1.2) · JavaScript action (node24)
<!-- /docs:generated header -->

A JavaScript action ships a bundle, and a composite action can run another action's bundle without naming it in a
`uses:`. This action works out, from the checkout alone, which bundles a set of actions needs, so a workflow builds
those and nothing else before it runs them. Pass its `build-dirs` to [`release/build-actions`](../build-actions).

The rules, applied transitively:

1. A JavaScript action (`runs.using: node<N>`) needs the files its `runs.pre`, `runs.main` and `runs.post` name.
2. A composite action needs every nested action its `run:` steps invoke through `$GITHUB_ACTION_PATH`,
   `${GITHUB_ACTION_PATH}` or `${{ github.action_path }}`, such as `node "$GITHUB_ACTION_PATH/helper/dist/index.js"`.
3. A composite action needs every action it names with `uses: ./<path>`.

A remote reference (`owner/repo/path@sha`) is never built: the runner downloads it with the bundle its ref carries.

## Usage

### Build what a pull request affects

```yaml
name: Build Affected Actions

on:
  pull_request:

permissions: {}

jobs:
  resolve:
    runs-on: ubuntu-latest
    permissions:
      contents: read # to fetch code
    outputs:
      build-dirs: ${{ steps.resolve.outputs.build-dirs }}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
          fetch-depth: 0

      - id: changed
        env:
          BASE_SHA: ${{ github.event.pull_request.base.sha }}
        run: |
          {
            echo 'files<<CHANGED_FILES_EOF'
            git diff --name-only "$BASE_SHA" HEAD
            echo 'CHANGED_FILES_EOF'
          } >> "$GITHUB_OUTPUT"

      - id: resolve
        uses: TimSchoenle/actions/actions/release/resolve-actions@actions-release-resolve-actions-v1.1.2 # tag=actions-release-resolve-actions-v1.1.2
        with:
          mode: affected
          changed-files: ${{ steps.changed.outputs.files }}
          exclude: scripts/templates

  build:
    needs: resolve
    if: needs.resolve.outputs.build-dirs != '[]'
    runs-on: ubuntu-latest
    permissions:
      contents: read # to fetch code
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      # set up the toolchain and install dependencies here
      - uses: TimSchoenle/actions/actions/release/build-actions@actions-release-build-actions-v1.1.2 # tag=actions-release-build-actions-v1.1.2
        with:
          build-dirs: ${{ needs.resolve.outputs.build-dirs }}
          build-command: npm run build
          artifact-name: built-actions-${{ github.run_attempt }}
```

## Behaviour

- **Targets, workflows or everything.** The candidates are `targets` plus every `uses: ./<path>` step of the listed
  `workflows`. With both empty, every directory holding an `action.yml` or `action.yaml` below `path` is a candidate,
  minus `exclude`, `node_modules` and `.git`. A manifest that does not parse fails the step once it is part of the
  closure, so exclude template directories.
- **Affected mode** keeps the candidates a changed file reaches: a file in an action directory of the candidate's
  closure, or in one of its source paths. A candidate that builds nothing is not affected by a lockfile change.
- **Source paths** are each action directory of the closure, the directory of every workspace package its build
  directories depend on through the `workspace:` protocol in `dependencies`, `optionalDependencies` or
  `peerDependencies` (transitively; `devDependencies` never reach a bundle), and whichever of `bun.lock`, `bun.lockb`,
  `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, `.bun-version`, `.node-version`,
  `.nvmrc` and `.tool-versions` exist at the root. A directory is written as `<dir>/**`.
- **Paths are repository-relative.** Every path in and out is POSIX-separated with no `..` segment; an absolute path
  or one that climbs out of the checkout fails the step.
- Nothing in the checkout is executed, and no token or network access is used. Symbolic links are not followed.
