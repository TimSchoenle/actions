# Release Install Built Actions

Downloads a release/build-actions artifact by ID, verifies every file against the manifest hash the build job published, and copies the bundles into a checkout, so the actions there run on bundles built from that commit.

[actions-release-install-built-actions-v1.1.0](https://github.com/TimSchoenle/actions/releases/tag/actions-release-install-built-actions-v1.1.0) · Composite action
<!-- /docs:generated header -->

The second half of [`release/build-actions`](../build-actions): run it after the checkout and before any step that
runs a local action with a bundle (`uses: ./actions/x`), and those steps run the bundles built from the commit under
test.

<!-- docs:generated usage -->
## Usage

### Run local actions on bundles built in this run

```yaml
name: Verify My Action

on:
  pull_request:

permissions: {}

jobs:
  # build: release/build-actions, publishing artifact-id and manifest-sha256 as job outputs

  test:
    needs: build
    runs-on: ubuntu-latest
    permissions:
      contents: read # to fetch code
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      # Before any step that runs a local action with a bundle.
      - uses: TimSchoenle/actions/actions/release/install-built-actions@7c1147cf1e275c068a8484fa9a2dcb38a8b1f92f # tag=actions-release-install-built-actions-v1.1.0
        with:
          artifact-id: ${{ needs.build.outputs.artifact-id }}
          expected-manifest-sha256: ${{ needs.build.outputs.manifest-sha256 }}
      - uses: ./actions/my/action
```

### Install into a second checkout, with the artifact record checked

```yaml
name: Verify Against A Test Repository

on:
  pull_request:

permissions: {}

jobs:
  # build: release/build-actions, publishing artifact-id, artifact-digest and manifest-sha256

  test:
    needs: build
    runs-on: ubuntu-latest
    permissions:
      actions: read # to look the artifact record up
      contents: read # to fetch code
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          repository: my-org/test-repository
          persist-credentials: false
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          path: tmp/actions-code
          persist-credentials: false
      - uses: TimSchoenle/actions/actions/release/install-built-actions@7c1147cf1e275c068a8484fa9a2dcb38a8b1f92f # tag=actions-release-install-built-actions-v1.1.0
        with:
          artifact-id: ${{ needs.build.outputs.artifact-id }}
          expected-manifest-sha256: ${{ needs.build.outputs.manifest-sha256 }}
          expected-artifact-digest: ${{ needs.build.outputs.artifact-digest }}
          github-token: ${{ github.token }}
          path: tmp/actions-code
      - uses: ./tmp/actions-code/actions/my/action
```

## Behaviour

- **Downloaded by ID, verified by hash.** The artifact is fetched by `artifact-id`, never looked up by name, into a new
  directory under `RUNNER_TEMP`. download-artifact runs with `digest-mismatch: error`, so an archive that differs from
  the digest the artifact service recorded at upload fails the download.
- **Nothing is copied before every check passes**: the SHA-256 of `bundles.json` equals
  `expected-manifest-sha256`; the manifest parses under its strict schema; the download holds no symbolic link or
  special file, no file the manifest does not list, and every file it does list; each file's size and SHA-256 match;
  `bundles.sha256` matches the manifest; every path is relative, has no `..` segment and lies inside a build directory
  the manifest declares.
- **The artifact record check is optional.** With `expected-artifact-digest`, the record from
  `GET /repos/{owner}/{repo}/actions/artifacts/{id}` must belong to the expected run, be unexpired and carry that
  digest. Within one pull request run the manifest hash already covers every byte, so the check is meant for a job
  that publishes what it installs.
- **`replace: true` clears each bundle's directory** (`dist/` for `dist/index.js`) before copying, so a file from a
  committed build cannot survive beside the installed one. A bundle that sits directly in its action directory, such
  as a root action's `index.js`, is overwritten on its own and its directory is never cleared. A target path that runs
  through a symbolic link in the checkout fails the step.
- **`BUILT_ACTIONS_MANIFEST`** is exported with the path of the verified `bundles.json`, outside the checkout, so a
  later step can check that the bundle it runs is the installed one.
- The composite runs its TypeScript with the `node` on the runner's `PATH`; a self-hosted runner needs Node.js 20 or
  later installed.
